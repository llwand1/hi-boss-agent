# ADR-0002 主动性 = 确定性交互枚举，而非模型行为

- 状态：DRAFT（2026-09-16，评审中）
- 上游：ADR-0001（主动性的授权与措辞分离）
- 决策人：llwan（老板）

## 背景

ADR-0001 把"模型不得自行决定是否主动开口"固化下来（闸门在代码、措辞在模型）。
但 ADR-0001 仍让一个运行时状态机去**动态判断**"此刻该不该开口"——只是把闸门从模型移到了代码。

老板在评审 BDP 企划时提出更彻底的思路：用**纯粹点击式**驱动主动开口，把问题变成
"排列组合 + 分类"——即把（访客当前可见区块 × 行为类型）离散化，查一张人工设计的
预设话术枚举表，命中即弹。模型完全不介入"是否主动"以及"主动说什么"。

## 决策

主动开口的决策权，从「运行时模型 / 状态机判断」改为「构建期确定的离散映射」：

- 行为信号只取离散、有限的分类变量（当前可见区块 + 少量行为类型，如进入区块 / 点击元素 / 主动开聊），不做连续行为流。
- 一张预设话术枚举表：区块 × 行为 → 邀请式话术（如"想听我讲讲 Web 实操吗？"）。
- 前端命中即弹出；不命中则沉默。模型只在被动问答闭环（/api/chat）中工作。
- 状态机降级为「额度 + 接待态管理器」：只管"本会话还能不能再说一次""HR 是否已进入接待态"，不再做任何开口判断。

## 与 ADR-0001 的关系

收敛而非矛盾。ADR-0001 的"闸门在代码"升级为"决策在预设枚举"：
过度主动的风险从根上消除——因为主动开口的判断根本不经过模型的任何能力
（闭源模型无法在该沉默时沉默的缺陷被**绕开**，而非被修复）。

## 采纳理由

1. 根因消除过度主动：决策点不在模型，闭源模型误报高的问题不再相关。
2. 零延迟主动话术：话术预生成，弹出即显示，直接受益体验层（呼应项目"技术重心放体验"）。
3. 完全可测可预期：评测 = 话术表覆盖度 + 误触发率，而非模型玄学行为。
4. 设计感 / 人格可控：话术精心写定，体现产品层能力，且不暴露监控感。
5. 隐私感更好：粗粒度区块分类，而非实时行为流。

## 接受的代价 / 边界（证伪）

- 组合需约束：若维度过多（区块 × 行为 × 历史 × 时间）话术会爆炸。约束为单一分类变量（可见区块）+ 少数行为类型，话术集合控制在 10–20 条。
- 机械感：主动开口本就是"邀请"而非"回答"，机械感低；可选让模型仅润色语气（默认不启用，保零延迟与确定性）。
- 放弃个性化主动：对"打招呼"场景够用——HR 不需要被个性化主动，分类式轻推足矣。
- 不否定 agent 闭环：被动问答 → 工具 → 回答 的闭环仍在；只是"主动"被剥离成确定性设计层。

## 落地形态

- `resume.json` 新增 `proactive` 字段：
  - `sections`：区块 → 邀请话术（枚举）
  - `triggers`：行为类型 → 话术（可选叠加）
- SPEC 修订：原"五姿态状态机决定开口"改为"前端离散分类 → 预设话术枚举；状态机只管额度与接待态"。
- 评测指标：误触发率（应沉默却开口）目标 ≤20%，用 SPEC §10 场景集回归。

## Open Question（待老板确认）

1. 分类维度是否只取"当前可见区块"，还是纳入更多离散行为（点击具体元素 / 复制文本）？
2. 话术枚举由谁撰写定稿（老板口述原话 → 固化进 resume.json）？
3. 是否保留"模型仅润色语气"的可选项（默认关闭）？

## 复核条件（什么情况下应推翻本 ADR）

- 若某天模型切换为可精确控制主动性的开源 / 微调模型，且评测误报率显著低于预设枚举的覆盖率缺口 → 可考虑回退到 ADR-0001 的动态判断。
- 若业务需要真正的个性化主动（如"根据这个人具体兴趣动态生成邀请"）→ 纯枚举不够，需引入模型，但应加硬闸门与评测护栏。
