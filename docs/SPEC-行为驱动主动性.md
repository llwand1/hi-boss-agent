## 0. 一句话

**v0.2.0 口径（现行）**：访客看到板块 → 前端按「区块 × 行为」查一张**人工写定的话术枚举表** → 命中即弹，不命中就沉默；模型**完全不参与主动开口**，只在被动问答（`/api/chat`）里回答内容。

核心原则没变，只是落点更狠：

> **开口由查表决定，措辞由人预先写定；模型只管「回答」，不管「搭话」。**

> **[v0.1.0 原文（已由 ADR-0002 撤销，保留沿革）]**
> 「把访客的浏览行为（停留、回看、滚动节奏、点击）实时压缩成一句状态描述，喂给模型当上下文；同时用代码侧的状态机决定『此刻该不该开口』。」
> 「闸门在代码里，措辞在模型里。」
> 撤销理由与影响条款清单见 §3.4。

## 1. Objective（目标）

### 1.1 要解决什么问题

当前 harness 是**被动的**：只有访客先打字，agent 才有反应。它的「主动性」是一次性的计时器（实测在 `index.html:717-719`，`scheduleTip()` 每 18–36 秒随机弹一次气泡；SPEC v0.1.0 记录的 `707-711` 已因后续提交漂移），与访客此刻在做什么**完全无关**——这正是「骚扰感」的来源。

本特性要解决的不是「让它多说话」，而是：**让开口的时机对得上访客正在看的东西**。

### 1.2 为什么这是本项目的核心机制，而非锦上添花

本项目的产品定位 = **替 llwan 向一个陌生人（多半是 HR）开口打招呼**。

打招呼的质量不取决于说得多，而取决于**说的时机对不对**。读不到空气的打招呼是骚扰，读到空气的才叫会说话。因此行为感知不是附加功能，是这个产品成立的前提。

### 1.3 用户故事与验收判据（可实测）

| # | 用户故事 | 验收判据 |
|---|---|---|
| US-1 | 作为 HR，我在技能栏停留了一会儿，AI 主动问的和技能相关 | 主动开口话术与当前板块匹配率 ≥ 90%（20 次抽样） |
| US-2 | 作为 HR，我只是切过来扫一眼就走，AI 不该打扰我 | 页面不可见或停留未达阈值时，主动开口次数 = 0 |
| US-3 | 作为 HR，我关掉了聊天面板，AI 不该再追着我说 | 关闭面板后本会话主动开口次数 = 0 |
| US-4 | 作为 HR，我问了「怎么联系你」，AI 直接给我留联入口 | 访客问到联系方式时，留资入口在一次回复内出现 |
| US-5 | 作为 HR，我感觉不到自己被监控 | 话术中不出现具体秒数、次数、滚动等「监控感」数据 |
| US-6 | 作为主人，我能看到访客在看哪块、弹过几次 | admin 看板显示 focus（板块）+ 主动弹出次数 + 留资转化 |

> **v0.2.0 校正**：US-2 原写「有效停留 < 5s」（依赖 §5.2 连续有效停留计时，已由 ADR-0002 撤销），改为不依赖该机制的表述；US-4 原写「命中 SEEKING 姿态」、US-6 原写「显示 stance / 有效停留」，同理降级。三项判据的**意图未变**，只是不再要求运行时状态机。

## 2. 依据与先例（不凭印象）

### 2.1 学术先例：Proactive Agent（ICLR 2025）

- 论文：*Proactive Agent: Shifting LLM Agents from Reactive Responses to Active Assistance*（Yaxi Lu 等，ICLR 2025）
- 做法：采集真实人类活动数据（键盘、鼠标、剪贴板、浏览器活动）→ 生成主动任务预测 → 人工标注接受/拒绝 → 训练奖励模型当自动评估器 → 构建 **ProactiveBench**（6,790 事件）→ 微调模型。
- 成绩：微调后 Qwen2-7B 在 ProactiveBench 上 **F1 = 66.47%**，优于所有开源与闭源模型；奖励模型与人类判断一致性 F1 = 91.80%。

**对你的思路最直接的两条推论（来自论文原文结论）**：

1. **闭源模型倾向于过度主动，在用户不需要帮助时无法保持沉默，误报率高。** → 我们用 Agnes（闭源），所以**绝不能让模型自己决定要不要开口**。**v0.2.0 按此推论推到底**：不是「用代码闸门挡住模型的开口冲动」，而是「主动开口这件事根本不经过模型」——见 ADR-0002。
2. **让模型一次预测多个候选任务再筛选，准确率显著提升**（GPT-4o-mini F1 从 52.15% → 78.80%）。→ 可借鉴：让模型产出候选动作 + 自检「这次该不该说」，而不是直接产出话术。（v0.2.0 下本条**暂不采用**，因为开口已改为查表；若将来回到动态判断，此条生效。）

### 2.2 产业先例

- 数字名片（Linq / Popl / Tapni）有 analytics 无 AI；开源简历 agent 有对话无获客闭环。**「行为信号 → 主动接待」在个人简历场景没有成例** —— 这点此前已查证，仍是空白。

### 2.3 证伪：这个思路会在哪里失败

| 失效模式 | 触发条件 | 后果 | 本 SPEC 的对策 |
|---|---|---|---|
| **F1 停留≠兴趣** | 访客切标签页泡咖啡、批量扫库、爬虫 | 基于脏信号自信地说错话，比不说话更糟 | 有效停留定义（§5.2）+ 信号分级（§5.3） |
| **F2 反向伤害体验** | 行为数据进 prompt 导致上下文变长 | 首字延迟上升，直接违背本项目第一体验指标 | 状态压缩成 ≤120 字符一行（§6.3） |
| **F3 被监视感** | 话术暴露「你在技能栏停了 47 秒」 | 信任崩塌，产品死亡 | 隐私红线（§7）+ 话术禁令 |
| **F4 玄学化** | 直接把事件流水塞进 prompt | 无法测试、无法调参、无法解释 | 行为先变状态（§6），状态可测可看 |
| **F5 过度主动** | 复用现有 18–36s 随机弹窗 | 骚扰，HR 关站 | 删除随机弹窗，改由状态机授权（§6.2） |

> **v0.2.0 校正（哪些失效模式已不存在）**：采用 ADR-0002 的查表方案后，**F2（prompt 变长导致首字延迟）与 F4（事件流水塞进 prompt → 玄学化）从源头消失**——行为数据不再进入任何 prompt。F1（停留≠兴趣）、F3（被监视感）、F5（随机弹窗骚扰）三条**仍然有效**，是本轮实现真正要处理的对象。F5 的对策措辞由「改由状态机授权」改为「改由 §6A 的查表 + 额度触发」。

## 3. 对原思路的修正（关键）

| 老板的原思路 | 本 SPEC 的修正 | 理由 |
|---|---|---|
| 行为 → 提示词（直接） | **行为 → 状态机 → 提示词** | 行为是高频噪声，状态是低频结论。模型不该看流水账，该看结论；且状态机可测试、可 A/B、可降级 |
| 行为影响「说什么」 | **先影响「说不说」，再影响「说什么」** | 主动性的本质不是敢开口，是**该闭嘴时能闭嘴**（论文已证闭源模型最缺这个） |
| 记录行为用于差异 | **会话内有效，不跨会话追踪个人** | 隐私红线（§7） |

## 4. 架构决策摘要（完整版见 ADR-0001 + ADR-0002）

### 4.1 现行架构（v0.2.0，依 ADR-0002）

**决策：主动开口的决策权归构建期写定的枚举表；模型只做被动应答。**

```
IntersectionObserver（现有） → currentSection（现有）
            ↓
   查 resume.json 的 sectionTips[区块]（构建期由人写定，现有 7 条）
            ↓
   [额度/接待态管理器]（唯一运行时判断，最薄一层）
     · 本会话已弹次数 < 上限？
     · 面板未打开过？（现有 index.html:478 已实现「打开过一次后停止自动提示」）
     · 停留达到阈值？（现有 6s）
            ↓ 放行                       ↓ 否决
   直接显示预写话术（零延迟、零模型调用）    静默
```

- **零模型参与主动**：主动气泡不调用 `/api/chat`，因此没有延迟、没有误报、没有 token 成本，措辞 100% 可控。
- **运行时判断只剩三问**，全是可断言的布尔量，不再是五姿态转换图。
- 模型的位置只有一个：访客主动开聊之后的被动问答（`/api/chat`）。
- 兜底天然存在：话术本身就是写死的，模型挂不影响主动层（反而主动层不依赖模型）。

> **现状机制的精确语义（实测，写准以免下轮实现照错的样子改）**
> - `armDwell()`（`public/index.html:627-636`）是**闲置计时**而非停留计时：`scroll` / `pointerdown` 任一事件都重置 6s 计时器，所以气泡出现在「访客停下来」时——这恰好是 ADR-0002 想要的时机，**不要改成累计停留**。
> - `adaptiveTip()`（`:620-626`）在面板开启时直接 return，气泡本身 `showTip()` 显示 5s 后自动收起（`:491-497`）。
> - **没有额度计数器**：额度上限目前只由一条规则间接提供——访客**第一次打开面板后 `tipTimer` 被 clear，自动提示永久停止**（`:478`）。在访客不开面板的路径上，气泡是**无限次**的（`:717-719` 每 18–36s 重复弹上一次的文本）。这就是 N1 + N2 要合起来补的那一格。

### 4.2 v0.1.0 架构原文（已由 ADR-0002 撤销，保留沿革）

**决策：主动性的授权权归代码，措辞权归模型。**

```
行为采集层（前端）  →  状态机（前端，纯函数）  →  [闸门]  →  状态行（≤120字符）  →  模型
                                                   │
                                                   └─ 闸门否决：不调用模型，直接静默
```

- 状态机是**纯函数**：`(events, prevState) → newState`，可单测、可回放。
- 模型只被允许在闸门放行后生成话术；模型不得自行决定「要不要发消息」。
- 模型挂了/超时：状态机仍可驱动规则兜底话术（`resume.json` 已存板块话术）。

> 撤销理由：ADR-0002 指出上述方案仍把「该不该开口」交给**运行时**判断（只是从模型搬到代码）。查表方案把决策点移到**构建期**，过度主动的风险从根上消除，且主动气泡零延迟。ADR-0001 的「模型不得自行决定开口」这条底线**未被推翻**，只是被更彻底地执行。

## 5. 信号层（Signals）

> **[v0.2.0 墓碑]** 本节按 ADR-0002 **整体降级为可选储备**：现行方案只使用 §5.1 里的 `dwell`（区块停留）与 `panel_open/panel_close`（面板开关）三项，其余连续行为信号（回看、选中复制、滚动速率、bot_like）**不采集、不进 prompt**。保留原文是为了将来若回到动态判断时不必重新设计。作废明细见 §3.4。

### 5.1 信号字典

| 信号 | 采集方式 | 可信度 | 语义 |
|---|---|---|---|
| `dwell` 板块停留 | IntersectionObserver + 有效停留计时 | 中 | 在看这块 |
| `scroll_slowdown` 滚动减速 | 滚动位移/时间比值下降 | 中 | 看进去了 |
| `revisit` 回看（离开后再回到同一板块） | 板块切换序列检测 | **高** | 真感兴趣，最强的隐式信号 |
| `select_copy` 选中/复制文本 | `selectionchange` / `copy` | **高** | 在做笔记 = 真在看 |
| `contact_click` 点击邮箱/GitHub | 点击监听 | **极高** | 已在考虑联系 |
| `panel_open` 打开对话面板 | 现有已实现 | **极高** | 愿意互动 |
| `panel_close` 关闭面板 | 需新增 | **负信号** | 不想被打扰 |
| `fast_scroll` 快速划过（>2 屏/秒） | 滚动速度 | 中 | 在找东西 / 没兴趣 |
| `idle_blur` 失焦 > 30s | `visibilitychange` + `blur` | — | **有效停留归零**（防挂机） |
| `bot_like` 无滚动无鼠标、<2s 直达底部 | 启发式 | — | 疑似爬虫，整体降级为 COLD |

### 5.2 有效停留（防 F1）

有效停留 = 满足以下**全部**条件的时间累计：

1. `document.visibilityState === 'visible'`
2. 窗口处于焦点（`window.onfocus`）或 30s 内有交互事件
3. 当前有板块处于视口内且 `intersectionRatio > 0.4`

任一条件不满足 → 计时暂停（不停表归零，暂停计时）。

### 5.3 信号分级

- **弱信号**（dwell、scroll_slowdown）：只影响语气与推荐问题，**不得**单独触发主动开口。
- **强信号**（revisit、select_copy、contact_click）：可触发主动开口。
- **负信号**（panel_close、fast_scroll 连续 2 次）：进入 RESTING 冷却。

## 6. 状态层（Stance Machine）

> **[v0.2.0 墓碑]** §6.2 转换规则、§6.3 状态行**已作废**；§6.1 五种姿态**降级**为看板记账标签（记录「这位访客是高意向还是随便扫一眼」），**不再作为开口判据**——开口判据见 §4.1 的三问。下表保留原样，其「主动开口额度」列的含义改为由 §4.1 的额度计数器提供，与姿态本身脱钩。

### 6.1 五种姿态

| 姿态 | 进入条件 | 主动开口额度 | 允许话术 | 可提留联 |
|---|---|---|---|---|
| `COLD` 冷启动 | 进入 <8s 或有效停留 <5s 或 `bot_like` | 0 | — | 否 |
| `BROWSING` 浏览中 | 有效停留 ≥5s + 有滚动微动 | 1 次 | 贴合板块的开放式提问 | 否 |
| `ENGAGED` 有意向 | 出现任一强信号，或已在面板对话 ≥1 轮 | 累计 ≤2 次 | 深入展开，可邀请留联 | 是（仅 1 次） |
| `SEEKING` 索取中 | 问到联系方式/到岗/面试/薪资，或打开留资表单 | 0（改为应答模式） | 直接给信息 | 是 |
| `RESTING` 冷却 | `panel_close` / 明确拒绝 / 失焦 >30s | 0 | — | 否 |

### 6.2 转换规则（硬编码，不在模型里）

```
进入页面 ──> COLD
COLD     ──(有效停留≥5s 且非 bot_like)──> BROWSING
BROWSING ──(强信号 或 面板首轮对话)──> ENGAGED
ENGAGED  ──(命中索取意图关键词 或 打开留资表单)──> SEEKING
任意     ──(panel_close / 明确拒绝 / 失焦>30s)──> RESTING
RESTING  ──(冷却 10 分钟 或 访客主动开口)──> BROWSING
```

补充规则：
- **额度只减不增**：单会话主动开口上限 2 次，达到上限后永久静默（除非访客主动说话）。
- `bot_like` 命中 → 强制 COLD 且不恢复。

### 6.3 状态行（喂给模型的唯一行为上下文）

格式（≤120 字符，置于 system prompt 末尾，每次请求重新生成）：

```
[访客状态] 姿态=ENGAGED|关注=技能|有效停留=23s|已主动=1/2|最近动作=复制了邮箱
```

禁令：
- 状态行**不进入**对话历史，只进 system prompt。
- 不得把事件流水、时间戳序列、原始坐标塞进 prompt。
- 增量 token 预算：**≤ 120 字符**（防 F2）。

### 6.4 差异化的三个落点

| 落点 | 受什么影响 | 例子 |
|---|---|---|
| **说不说** | 姿态 + 额度 + 闸门 | COLD/RESTING/SEEKING 一律静默 |
| **说什么** | 关注板块 + 姿态 | BROWSING 给开放式提问；SEEKING 直接给联系方式入口 |
| **给什么** | 姿态 | 仅 ENGAGED/SEEKING 显示留资入口；其余隐藏 |

## 7. 隐私红线（Never 级）

1. **只做会话内**：状态存 `sessionStorage` / 内存，不落 `localStorage`，不跨会话串联。
2. **不采集身份**：不读 cookie、不做指纹、不记 IP 与 UA 到个人维度。现有 `/api/event` 保持只记 `{type, section, ts}`。
3. **不出现监控感话术**：禁止「你在技能栏停了 47 秒」「你滚动了 3 次」这类表述。允许的是自然表达：「看你一直在看技能这块，要不要我细讲讲？」
4. **明示而非炫技**：首次主动开口时，面板内给出一行小字说明「我会根据你正在看的内容调整回答，不会记录你的个人信息」。
5. **一键关闭**：面板内提供「别主动找我」开关，打开后强制 COLD。

## 11. 代码风格

- 前端：ES5 兼容写法（现有 `index.html` 全篇 `var` + `function`），**保持零依赖、单文件可离线打开**。
- 状态机写成纯函数，便于单测：

> **[v0.2.0 墓碑]** 下面这段 `nextStance()` 是 v0.1.0 方案的示例，随 §6.2 一起作废，**不要照它实现**。v0.2.0 需要的运行时判断只剩 §4.1 的三问（面板是否开过 / 弹次是否用满 / 是否停下 6 秒），一个计数器 + 一个布尔量即可，无需纯函数状态机、也就无需为其写单测。

```js
function nextStance(prev, signal, ctx) {
  if (signal === 'panel_close') return 'RESTING';
  if (ctx.botLike) return 'COLD';
  if (prev === 'RESTING' && !ctx.cooledDown) return 'RESTING';
  if (ctx.seekingIntent) return 'SEEKING';
  if (prev === 'COLD' && ctx.effectiveDwell >= 5) return 'BROWSING';
  if (prev === 'BROWSING' && signal.strong) return 'ENGAGED';
  return prev;
}
```

- 命名：`snake_case` 事件名，`camelCase` 变量，`SCREAMING` 常量。
- 注释写「为什么」不写「做什么」。

## 15. Boundaries

**Always**
- 改动前先更新本文档，再改代码（spec 是活的）
- 每个任务完成即跑验证步骤并勾选
- 状态行长度、无身份信息、额度上限三项每次改动后回归
- 提交前 `node --check` 所有改动的 JS

**Ask first**
- 新增采集信号（涉及隐私边界）
- 改变五姿态定义或转换规则
- 引入任何第三方依赖（本项目坚持零依赖）
- 修改 `resume.json` 的结构字段（会影响模板化）

**Never**
- 让模型自行决定是否主动开口（论文已证闭源模型误报率高）
- 在话术中暴露具体秒数、次数、滚动等监控感数据
- 跨会话追踪个人、记录 IP/UA 到个人维度
- 把密钥写入代码或提交 `.env.local`
- 删除失败/跳过的测试来让流程变绿

## 19. 项目治理约定（本仓库按正式项目要求）

- **版本**：SPEC / 重要文档头部带 `vX.Y.Z` + 状态标记（`[SPEC-DRAFT]` / `[WIP]` / `[STABLE]`）。
- **变更登记**：新增 `CHANGELOG.md`，每次特性改动按 Conventional Commits 风格登记一条。**→ v0.2.0 本轮已补建**（v0.1.0 写了这条门禁却没建文件）。
- **决策记录**：架构级决策写 `docs/ADR-XXXX-*.md`，一决策一文件，只增不改（改了就写新的 ADR  supersede）。
- **单一事实源**：内容在 `resume.json`，提示词逻辑在 `shared/prompt.mjs`，禁止在别处复制第二份。
- **门禁**：改 `resume.json` 后必须跑 `node tools/gen-resume.mjs`；JS 改动必须 `node --check`；每次提交不得包含 `.env.local`、`leads.json`、`events.json`。

### 19.1 v0.2.0 对治理约定自身的两条修正

1. **门禁的语法自检要分模块制式**：`functions/api/*.js` 是 ESM，`node --check` 按 CJS 解析会**必然误报**（实测 5/5 FAIL，按 ESM 校验 5/5 OK）。自检命令改为：`.mjs` 用 `node --check`，`functions/api/*.js` 用 ESM 方式校验（N8 落成脚本）。
2. **文档版本号要与 git tag 对齐**：本仓库当前 **0 个 tag**，4 个 commit 全靠 `git log` 找。此后每次 SPEC/ADR 版本升级同步打一个 tag（如 `spec-bdp-v0.2.0`），使「文档说的是哪一版」可被机器验证。

> **本次收敛暴露的流程缺陷（记此以免重犯）**：ADR-0002（2026-09-16）已把 BDP 的主机制换掉，但 SPEC 直到 2026-09-19 才同步——中间 3 天里，§15「改动前先更新本文档」这条 Always 约束被违反了 1 次，而 §14 任务清单的「未开始」状态掩盖了「其实一半已作废、一半已被现有代码超越」。文档活着不等于文档对。
