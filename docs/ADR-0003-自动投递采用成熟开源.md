# ADR-0003：自动投递（outbound）采用成熟开源，不自研

- 状态：已采纳
- 日期：2026-09-19
- 背景任务：把「会打招呼的简历 Agent」从"被动等 HR 来问"扩展为"能按 JD 主动打招呼、乃至自动投递"

## 一、问题

要不要自己写一个"自动投递到 Boss直聘/智联"的浏览器 Agent？

## 二、结论

**不自研。分两层，各用各的：**

| 层 | 归属 | 实现 |
|---|---|---|
| **inbound**（HR 看简历时对话） | 本项目 | 自研，已上线（`/index.html` + `/api/chat`） |
| **判断/措辞**（按 JD 判匹配度、写招呼语） | 本项目 | 自研，已有（`/jd.html` + `/api/jd-greeting`） |
| **outbound 动作**（登录平台、批量发招呼语、发图片简历） | **成熟开源** | 采用 `loks666/get_jobs`，不重写 |

一句话：**开源负责"手"（点按钮、发消息、过验证），我们负责"脑"（按真实简历判断与措辞）。**

| 项目 | 语言 / 热度 | 覆盖国内平台 | 招呼语可否被我们接管 | 维护 | 协议 |
|---|---|---|---|---|---|
| **loks666/get_jobs** | Java / 8.4k★、660 commits | Boss、猎聘、51job、智联 | ✅ **提示词模板可自定义**（见下） | 2026-09-16 仍活跃 | PolyForm Noncommercial 1.0.0 |

**主选 `get_jobs`**——它是唯一"真正跑国内平台 + 自带按 JD 生成招呼语 + 该提示词用户可自定义 + 仍在维护"的组合。
career-ops / BossHunter 留作备选（前者做 JD 评估与定制简历很强；后者"投递前必须人工确认"的哲学与本项目 ADR-0001 一致，若将来要更保守可切换）。

## 四、接入契约（实读 `Boss.java` 得出，这是本 ADR 的核心）

`get_jobs` 生成招呼语时：

```java
String requestMessage = (prompt != null)
    ? String.format(prompt, introduce, keyword, jobName, jd, config.getSayHi())
    : buildDefaultPrompt(introduce, keyword, jobName, jd);
// 拿到结果后：
return result.toLowerCase().contains("false") ? config.getSayHi() : result;
```

推导出三条硬约束：

1. **`prompt` 就是注入点**：网页端「AI 配置」里的 `prompt` 字段，用 `String.format` 按序填入 5 个值 ——
   `%1$s`=个人介绍(introduce)、`%2$s`=搜索关键词、`%3$s`=岗位名、`%4$s`=JD 全文、`%5$s`=兜底招呼语。
   我们可以把 `shared/prompt.mjs` 那套"只用真实简历信息、不编造"的判断逻辑原样塞进这个模板。
2. **模板里字面 `%` 必须写成 `%%`**（否则 `String.format` 抛 `UnknownFormatConversionException`）。
3. **模型输出不得含 "false"**（否则被判失败、回落到固定招呼语）。模板必须强制"只输出招呼语本身"。

## 五、边界（明确不做什么）

- ❌ 不在本项目里写爬虫/浏览器自动化 —— 那是 `get_jobs` 的职责，封号与 ToS 风险也随它。
- ❌ 不把投递逻辑塞进 Cloudflare 静态站 —— 它需要本地 Chrome + 登录态，天然是本地工具。
- ❌ 不做验证码绕过 —— `get_jobs` 遇滑块是"暂停等人工"，我们沿用。
- ✅ 我们唯一的 outbound 交付物：**把 `resume.json` 编译成 `get_jobs` 的 `introduce` + `prompt`**（见 `tools/export-outbound.mjs`）。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| Boss 风控 / 封号 | 低频（`get_jobs` 有 `wait_time` 降速）；只投匹配度高的；遇验证页人工过 |
| 协议变更 | `get_jobs` 已于 2026-09-16 由 MIT 改为 PolyForm Noncommercial：**个人求职可用，禁止商用** |
| 环境依赖重 | 需 JDK 21 + Maven + Chrome；**运行时必须关闭梯子**（国内平台 + 代理 = 触发风控） |
| AI 费用 | `get_jobs` 官方实测：Boss 每日投递跑完约 $0.06（gpt-5-nano 量级）；可复用本项目同一把 key |
| 招呼语质量不受控 | 由第五条接入契约接管 —— 用我们自己的提示词模板，缺陷点写进模板约束 |

## 七、落地步骤（前两步本项目已给成品，后几步需本人操作）

1. ✅ 本项目产出 `outbound/get_jobs.md`（`introduce` + `prompt`，可直接复制粘贴）
2. ✅ 本文档（边界与契约）
3. ⏳ 本人：装 JDK 21 + Chrome → `git clone get_jobs` → 下载 `getjobs.db.template` 改名 `getjobs.db` 放 `db/`
4. ⏳ 本人：`.env` 填 `BASE_URL / API_KEY / MODEL`（可复用本项目同一把 key）
5. ⏳ 本人：网页端把第 1 步的 `introduce` + `prompt` 粘进「AI 配置」，配 `keywords` / `city` / `期望薪资`
6. ⏳ 本人：**先开调试模式空跑一轮**（只遍历不投递），确认招呼语质量，再正式低频投递
